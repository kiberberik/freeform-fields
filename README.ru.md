# WP Freeform Fields

**Бесплатный плагин произвольных полей для WordPress с открытым кодом. Создан по мотивам ACF PRO и совместим с его данными.**

[Сайт и документация](https://wpff.kiberberik.link/ru/) · [English version](README.md) · [Руководство разработчика](docs/developer-guide.ru.md) · [Список изменений](CHANGELOG.md) · [Как помочь проекту](CONTRIBUTING.md)

WP Freeform Fields добавляет в WordPress:

- группы полей;
- повторители и гибкое содержимое;
- страницы настроек;
- блоки на PHP-шаблонах.

Всё бесплатно под лицензией GPL, «Pro»-версии нет.

Значения хранятся в том же формате, что у Advanced Custom Fields. Функции для шаблонов те же (`get_field()`, `have_rows()`…), поэтому сайт на ACF можно перевести без конвертации данных и правки темы.

> **Проект не связан с ACF и WP Engine.** WP Freeform Fields — независимый проект. Он не связан с WP Engine и командой Advanced Custom Fields, не одобрен и не спонсируется ими. «Advanced Custom Fields», «ACF» и «ACF PRO» — товарные знаки WP Engine. Здесь они упоминаются только для описания совместимости. Код плагина написан с нуля и не содержит кода ACF.

**Требования:**

- WordPress 6.5+ и PHP 8.1+;
- для Block Bindings в редакторе — WordPress 6.7+;
- для Abilities API — WordPress 6.9+.

## Возможности

### Поля

- **Конструктор групп полей** в админке:
  - перетаскивание мышью и с клавиатуры;
  - настройки каждого типа поля;
  - правила размещения;
  - условная логика;
  - копирование, корзина с отменой;
  - предупреждение о несохранённых изменениях.
- **35 типов полей:**
  - базовые: Text, Textarea, Number, Range, Email, URL, Password;
  - контент: Image, File, WYSIWYG, oEmbed, Gallery;
  - выбор: Select, Checkbox, Radio, Button Group, True/False;
  - связи: Link, Post Object, Page Link, Relationship, Taxonomy, User — с поиском и двусторонними связями;
  - дополнительные: выбор даты, даты и времени, времени, цвета и **карта**. Без ключа API карта работает на OpenStreetMap, с ключом — на Google Maps;
  - разметка: Message, Accordion, Tab, Group, **Repeater** (с постраничным выводом), **Flexible Content**, Clone.
- **Правила размещения** в формате ACF: тип записи, шаблон, рубрика, таксономия, роль, страница настроек, блок и свои правила.
- Где хранить группы:
  - в **PHP-коде**;
  - в базе;
  - в **Local JSON** в теме, со статусом «Sync available».

### Экраны

- Записи и страницы, в классическом и блочном редакторе.
- Рубрики и профили пользователей.
- **Страницы настроек** — из кода или из админки.
- **Типы записей и таксономии** — без кода.

### Блоки

- **Блоки на PHP-шаблонах**: `wpff_register_block_type()` или `block.json` с ключом `acf` / `wpff`.
- Живое превью и форма полей в боковой панели.
- Поддержка **InnerBlocks**.
- Данные блока хранятся в формате ACF.
- Источник **Block Bindings** `wpff/field`: значения полей выводятся в стандартных блоках (абзац, заголовок, изображение, кнопка) без шаблона.

### Для разработчиков

- Функции как в ACF:
  - `get_field()`, `the_field()`, `get_fields()`, `update_field()`;
  - `have_rows()`, `the_row()`, `get_sub_field()`, `add_row()`;
  - `acf_add_local_field_group()`, `acf_add_options_page()`, `acf_register_block_type()` и другие.
- Версии всех этих функций с префиксом `wpff_` доступны всегда.
- Хуки `wpff/load_value`, `wpff/format_value`, `wpff/update_value`, `wpff/validate_value` и `wpff/prepare_field`, с вариантами `/type=`, `/name=` и `/key=`.
- **REST API**: значения в свойстве `acf` у `wp/v2`. Запись тем же запросом проходит ту же проверку, что формы.
- **WP-CLI**: `wp wpff list | export | import | sync | import-acf`.
- **Abilities API** (WordPress 6.9+): ИИ-агенты и другие клиенты читают группы и значения полей с правами пользователя.
- Хранилище `wp.data` с именем `wpff/fields` — чтение и изменение значений формы из JavaScript.
- **Перенос из ACF** — из «Инструментов» или через WP-CLI. Переносятся группы полей, типы записей, таксономии и страницы настроек из базы. Ключи полей сохраняются, поэтому уже сохранённые значения сразу читаются.

### Качество

- **Безопасность:**
  - проверки прав и nonce;
  - очистка HTML для пользователей без `unfiltered_html`;
  - REST API и Block Bindings не раскрывают закрытые записи, содержимое под паролем и email пользователей.
- **Производительность:**
  - неизменённые значения не перезаписываются;
  - новые значения пишутся одним INSERT;
  - все значения объекта читаются одним запросом.
- **Доступность:** подписи связаны с полями; вкладки, строки и поиск по карте работают с клавиатуры.
- **Переводы:** шаблон `.pot` и полный русский перевод.

## Быстрый старт

```php
add_action( 'wpff/init', function () {
	wpff_add_local_field_group( array(
		'key'      => 'group_book',
		'title'    => 'Книга',
		'fields'   => array(
			array( 'key' => 'field_book_isbn', 'name' => 'isbn', 'label' => 'ISBN', 'type' => 'text', 'required' => 1 ),
			array( 'key' => 'field_book_cover', 'name' => 'cover', 'label' => 'Обложка', 'type' => 'image', 'return_format' => 'url' ),
			array( 'key' => 'field_book_shop', 'name' => 'shop', 'label' => 'Магазин', 'type' => 'google_map' ),
		),
		'location' => array( array( array( 'param' => 'post_type', 'operator' => '==', 'value' => 'post' ) ) ),
	) );
} );
```

```php
// В шаблоне:
echo esc_html( get_field( 'isbn' ) );
printf( '<img src="%s" alt="">', esc_url( get_field( 'cover' ) ) );

$shop = get_field( 'shop' ); // array( 'address' => …, 'lat' => …, 'lng' => …, 'zoom' => … )
```

Другие примеры — в [руководстве разработчика](docs/developer-guide.ru.md) и в папке [examples/](examples/).

## Переход с ACF

1. Сделайте резервную копию сайта.
2. Установите и активируйте WP Freeform Fields рядом с ACF. Пока ACF активен, WP Freeform Fields ему не мешает: поля, файлы `acf-json`, блоки и имена функций ACF остаются за ACF.
3. Откройте **Custom Fields → Tools → Migrate from ACF**. Сначала прочитайте **проверку темы**: она покажет функции ACF и хуки `acf/…`, которые использует тема и которых нет в WP Freeform Fields. Затем выполните перенос. Через WP-CLI: `wp wpff import-acf --dry-run`, затем `wp wpff import-acf`.
4. Отключите ACF. Темы с `get_field()` продолжат работать: значения читаются там, где их сохранил ACF, а фильтры `acf/…` в теме (например, `acf/load_field`, который заполняет варианты) продолжат срабатывать.

Если отключить ACF до шага 3, сайт продолжит работать: группы полей и страницы настроек читаются из таблиц ACF (только чтение, в списке они помечены **ACF**), пока вы их не перенесёте. Вывод плагина [ACF to REST API](https://wordpress.org/plugins/acf-to-rest-api/) (маршруты `acf/v3/…` и свойство `acf`) тоже сохраняется, пока этот плагин активен, а ACF нет. Доступ строже: только поля групп объекта, видимость как в REST API ядра, а поля страниц настроек — только тем, кто может открыть страницу, если группа не показана в REST.

Файлы ACF JSON из папки `acf-json` тоже читаются. Группы, экспортированные из ACF в PHP, работают как есть.

Перед переводом рабочего сайта прочитайте раздел [Отличия от ACF](#отличия-от-acf).

## Поле «Карта» и внешние сервисы

Без ключа API карта работает на тайлах [OpenStreetMap](https://www.openstreetmap.org/) с поиском [Nominatim](https://nominatim.org/). Для Google Maps задайте ключ одним из способов:

```php
define( 'WPFF_GOOGLE_MAPS_API_KEY', 'ваш-ключ' );   // wp-config.php
wpff_update_setting( 'google_api_key', 'ваш-ключ' ); // или acf_update_setting(), как в ACF
```

К этим сервисам обращаются только экраны админки, где есть поле карты, и только чтобы показать карту и выполнить поиск, который запустил редактор. Сам плагин никуда данные не отправляет. Сервер тайлов и геокодер меняются фильтрами `wpff/fields/google_map/tiles` и `wpff/fields/google_map/geocoder_url`.

## Разработка

```bash
composer install
```

```bash
npm install && npm run build
```

```bash
bin/setup-dev.sh
```

`setup-dev.sh` ставит WordPress на SQLite в `.dev/wp` — без Docker и MySQL. Скрипт подключает плагин и демо-поля. Логин администратора сохраняется в `.dev/credentials`.

```bash
wp --path=.dev/wp server --port=8889
```

```bash
composer test
```

```bash
composer lint
```

```bash
npm run lint:js
```

Тесты (PHPUnit) запускаются на настоящем WordPress с отдельной временной базой. Подробности — в [CONTRIBUTING.md](CONTRIBUTING.md).

## Отличия от ACF

- В редакторе блоков незаполненное обязательное поле блокирует любое сохранение, включая черновик. ACF позволяет сохранить черновик.
- Постраничный вывод в Repeater только делит строки на страницы в редакторе. Все строки по-прежнему загружаются и сохраняются вместе, поэтому очень большие повторители открываются так же медленно, как без постраничного вывода.
- `the_field()` экранирует вывод через `wp_kses_post()`, как ACF начиная с 6.2.5. Страницы, выведенные старой версией ACF, могут отличаться мелочами разметки: порядком атрибутов или `;` в конце `style`. `get_field()` не экранируется.
- Раскладки Group `table` и `row` упрощены: `table` выводится как `block`.
- Форма блока — только в боковой панели. Режим редактирования прямо в блоке из старых ACF Blocks не сделан.
- Вкладки и аккордеоны работают в метабоксах записей. На экранах рубрик и пользователей поля выводятся списком.
- Условная логика проверяется только в браузере, как в ACF.
- `setFieldValue()` в хранилище `wpff/fields` не работает для картинок, файлов, связей и строк Repeater.
- Из API ACF есть только часть: функции шаблонов, `acf_form()`, распространённые `acf_get_*` и основные хуки `acf/…`. Проверка темы на экране переноса показывает, чего не хватает именно вашей теме.
- В `acf_form()` нет простого загрузчика: поля изображений и файлов во фронтенд-формах работают только у пользователей с правом загружать файлы.
- Интеграции с WPGraphQL пока нет.
